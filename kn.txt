Q1. Your Pod keeps restarting repeatedly. What will you do?
Meaning: Your application Pod starts and crashes repeatedly.

This condition is commonly called CrashLoopBackOff.

Steps to troubleshoot:

1. Check the Pod:
kubectl get pods


2. Describe the Pod:
kubectl describe pod <pod-name>


3. Check application logs:
kubectl logs <pod-name>


4. Check previous container logs:
kubectl logs <pod-name> --previous


5. Identify the error and fix it.

Possible reasons:
- Application crash.
- Incorrect configuration.
- Missing environment variables.
- Incorrect container command.
- Insufficient memory.
Exam answer: Check Pod status using kubectl get pods, inspect events using kubectl describe pod, and check logs using kubectl logs. Identify and fix the application or configuration error.
Q2. A Kubernetes Pod is stuck in Pending state. What are the reasons and how will you troubleshoot it?
Meaning: Kubernetes has not been able to schedule the Pod onto a node.

Steps:

1. Check Pod status:
kubectl get pods


2. Describe the Pod:
kubectl describe pod <pod-name>


3. Check the Events section.

Possible reasons:
- Insufficient CPU or memory.
- Node unavailable.
- Persistent Volume not available.
- Incorrect node selector.
- Scheduling constraints.
4. Fix the identified issue.

Exam answer: Use kubectl describe pod to examine scheduling events. Check node resources, node availability, volume availability and scheduling constraints.
Q3. How would you debug a failed deployment in Kubernetes?
Steps:

1. Check deployments:
kubectl get deployments


2. Check Pods:
kubectl get pods


3. Describe deployment:
kubectl describe deployment mynginx


4. Check Pod logs:
kubectl logs <pod-name>


5. Check events:
kubectl get events


6. Fix the problem and verify the deployment.

Exam answer: Use kubectl get deployments, kubectl get pods, kubectl describe deployment and kubectl logs to identify and resolve deployment failures.
Q4. Multiple replicas exist, but some Pods are failing health checks. How will you identify the root cause and fix it?
Meaning: You have multiple copies of an application, but some are unhealthy.

Steps:

1. Check Pods:
kubectl get pods


2. Describe the unhealthy Pod:
kubectl describe pod <pod-name>


3. Check logs:
kubectl logs <pod-name>


4. Check readiness and liveness probe configuration.
5. Check application health and resource availability.
6. Correct the configuration or application issue.
Possible reasons:
- Incorrect health-check URL.
- Wrong application port.
- Application is taking too long to start.
- Insufficient resources.
- Application crashes.
Exam answer: Identify unhealthy Pods using kubectl get pods, inspect events and probes using kubectl describe pod, check logs and correct the health-check or application configuration.
