PART 6 – Create Dockerfile
Now we configure Docker to create an image containing our Java web application and Tomcat server.
Step 1. Create Dockerfile

Step 2. Write the Dockerfile

# Use Tomcat with Java 11 as the base image
FROM tomcat:9-jdk11

# Copy the generated WAR file to Tomcat webapps

# Expose Tomcat port
EXPOSE 8080

# Start Tomcat server

Let's understand each line.
Instruction	Meaning
FROM	Specifies the base image
COPY	Copies the WAR file into Tomcat
EXPOSE	Documents the port used by Tomcat
CMD	Starts the Tomcat server

Important difference from the screenshot in your manual:

The manual's Dockerfile screenshot uses:
COPY ./*.war /usr/local/tomcat/webapps/


That works if the WAR file is in the project root.

Our Maven-generated WAR file is inside target/, so we use:
COPY target/*.war /usr/local/tomcat/webapps/


This prevents a common Docker build error.

PART 10 – Troubleshooting Common Errors
These are the problems you may face during the practical examination.
Problem 1: Docker permission denied
Error:
permission denied while trying to connect to Docker daemon


Solution:

Use sudo before Docker commands.

Example:
sudo docker images


Problem 2: Docker container name already exists
Error:
Conflict. The container name "/app-demo" is already in use


Solution:

Stop and remove the existing container:
sudo docker stop app-demo


sudo docker rm app-demo


Now run it again:
sudo docker run -d --name app-demo -p 6060:8080 maven-web-app


Problem 3: Application is not opening
Check these things in order:

1. Is the container running?
sudo docker ps


2. Is Tomcat running inside the container?
sudo docker logs app-demo


3. Is port mapping correct?
sudo docker ps


Check for:
6060->8080


4. Is port 6060 allowed in AWS security group?

Check inbound rules.

5. Are you using the correct public IP and application path?
http://PUBLIC-IP:6060/maven-web-java/


Problem 4: Docker build fails – no WAR file found
Error:
COPY failed: no source files were specified


Solution:

First check:
ls target


If there is no WAR file, execute:
mvn clean package


Then build again:
sudo docker build -t maven-web-app .


Problem 5: Docker container exits immediately
Check:
sudo docker ps -a


Then:
sudo docker logs app-demo


The logs will help identify the problem, such as an invalid Dockerfile, missing WAR file or Tomcat startup failure.

Your manual contains 10 scenario-based questions on pages 4 and 5. These are important for your practical examination.

Q1. You have an index.html file on your laptop and launched an EC2 instance with Amazon Linux 2. The instance is running, but the public IP doesn't load the page. How will you host index.html?
Answer:

Step 1: Connect to EC2 using SSH.

Step 2: Install Apache HTTP server.
sudo yum install httpd -y


Step 3: Start Apache.
sudo systemctl start httpd


Step 4: Enable Apache.
sudo systemctl enable httpd


Step 5: Copy index.html into:
/var/www/html/


For example, after uploading the file:
sudo cp index.html /var/www/html/


Step 6: Allow HTTP port 80 in the EC2 security group.

Step 7: Open:
http://PUBLIC-IP


Q2. You deployed index.html to /var/www/html/, but the webpage is not loading. What two possible issues would you check?
Answer:

1. Check whether the Apache service is running.
sudo systemctl status httpd


2. Check whether HTTP port 80 is allowed in the EC2 security group's inbound rules.

Also verify that the file exists and has appropriate permissions.
Q3. Apache stops after an instance reboot. What command ensures it automatically starts on boot?
Answer:
sudo systemctl enable httpd


This enables Apache to start automatically whenever the EC2 instance boots.
Q4. You are deploying a Maven web application, but Maven is not installed on EC2. How will you install it?
Answer:

For Ubuntu:
sudo apt update
sudo apt install maven -y


Verify:
mvn -version


For Amazon Linux 2, you can use:
sudo yum install maven -y


Q5. You built a Maven project and generated a WAR file inside target/. Where will you place the WAR file for Tomcat deployment and why?
Answer:

Place the WAR file inside:
/usr/local/tomcat/webapps/


Tomcat automatically deploys WAR files placed inside its webapps directory.
Q6. Your Maven web application is deployed to Tomcat, but the browser displays 404 error. What will you check?
Answer:
1. Check whether Tomcat is running.
2. Check whether the WAR file is deployed correctly.
3. Check the application context path.
4. Check the URL entered in the browser.
5. Check Tomcat logs for deployment errors.
Example:

If the WAR file is:
maven-web-java.war


Access:
http://PUBLIC-IP:8080/maven-web-java/


Q7. You can access your application using curl localhost:8080 on EC2 but cannot access it from your browser. What AWS setting is missing?
Answer:

The EC2 security group's inbound rule is missing or misconfigured.

Allow the required application port, such as 8080.

For our experiment, that port is 6060 externally.
Q8. After stopping and restarting EC2, the public IP changes. Which AWS feature avoids this issue?
Answer:

Elastic IP.

Elastic IP provides a static public IPv4 address that can be associated with an EC2 instance.
Q9. You want to automate deployment commands whenever an EC2 instance is launched. Which EC2 feature can be used?
Answer:

EC2 User Data.

It allows us to execute scripts automatically during instance initialization.
Q10. Your Maven application needs external dependencies, but EC2 has no internet. What AWS service or change can allow the instance to download dependencies securely?
Answer:

Configure appropriate internet connectivity.
- For a public subnet, use an Internet Gateway with a suitable route.
- For a private subnet, use a NAT Gateway for outbound internet access.
Also ensure the security group and network ACL allow the required traffic.
